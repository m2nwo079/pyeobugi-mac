# 온보딩 시작 화면

온보딩 창의 첫 화면. 로고가 뜨고, 노트북이 올라오며 시작 문구가 나오고, 노트북 위 거북이가 혼자 움직인다.
"시작하기"를 누르면 노트북 화면이 무대를 덮을 만큼 커지고 남색으로 물든 뒤 권한 화면으로 넘어간다.
창 설정은 `docs/architecture.md`의 "온보딩·기준 잡기 창"을 따른다.

## 동작 요약

- 무대는 1280×832 좌표다. 창 크기에 맞춰 비율을 지킨 채 창을 덮도록 `max(너비 / 1280, 높이 / 832)`배로 키우고 가운데에 둔다. 창이 1280×832 고정이라 지금은 1배다.
- 시간 단위는 ms다. 모든 움직임은 `IntroClock`의 가상 시각으로 계산한다. 디스플레이 링크가 프레임마다 "창이 뜬 뒤 지난 시간"으로 시계를 옮기면, 그 사이 예약된 단계가 시각 순서대로 실행되고 레이어 값이 다시 계산된다.
- 그림과 좌표는 왼쪽 위가 원점이고 y가 아래로 커진다. 뷰의 `isFlipped`를 `true`로 두어 루트 레이어 한 곳에서 맞추고, 글자 레이어는 뒤집힌 컨텍스트에서 그대로 그린다.
- 모든 레이어의 `contentsScale`을 창의 `backingScaleFactor`에 맞추고, 창이 다른 배율의 화면으로 옮겨지면 다시 맞춘다. 로고는 벡터라 배율에 맞춰 다시 래스터화한다.
- 움직이는 부분마다 레이어를 한 번 만들어 두고, 프레임마다 변형(이동·회전·크기), 불투명도, 화면 사각형만 바꾼다.
- 창이 닫히거나(`willCloseNotification`), SwiftUI가 뷰를 치우거나(`dismantleNSView`), 남색 덮기가 끝나 권한 화면으로 넘어가면 `stop()`이 디스플레이 링크를 끊고 포인터 추적 영역을 지운다. 시계가 더 흐르지 않으므로 남은 단계도 실행되지 않는다.
- 시스템의 "동작 줄이기"가 켜져 있으면 모든 시간이 180 이하로 줄어 짧은 페이드만 남는다. 로딩 대기는 900, 점 깜박임·노트북 튀어 오름·착지 눌림·거북이 행동·시선 따라가기·클릭 반응은 하지 않는다. 노트북은 위치와 함께 불투명도 0 → 1로 나타난다.

## 그리는 방법

| 부분 | 방법 |
| --- | --- |
| 배경 (하늘 그라데이션, 산, 빛) | 2배 PNG `IntroBackground` (1280×832), 고정 이미지 레이어 |
| 노트북 본체 | 2배 PNG `IntroLaptop` (1196×808, 무대 (42, 24)), 노트북 레이어 안에서 함께 이동 |

| 노치 | `CALayer` 둥근 사각형, 이동 |
| 남색 덮기 | `CALayer` 배경색, 불투명도 |
| 로고 | 벡터 SVG `IntroLogo` (846×520, 무대 (217, −136)), 이동·불투명도 |
| "Loading"과 점 4개 | Core Text 글자 레이어. 점마다 레이어를 두고 불투명도 |

| 시작하기 버튼 | `CALayer` 둥근 사각형 + Core Text, 포커스 링은 `CAShapeLayer` |
| 거북이 다리·등껍질·지느러미 2개·머리·뜬 눈·감은 눈 | 4배 PNG `IntroTurtle*`, 부위별 레이어 변형 |

거북이는 등껍질·다리 층(화면 뒤)과 머리·지느러미 층(화면 앞) 두 덩어리로 나뉘어 노트북 화면 가장자리에 걸쳐 있다. 인사하는 동안만 지느러미를 머리 위로 올려 그린다.

### 시선 따라가기의 프레임 수 환산

따라가기 상수 0.14는 초당 60프레임에서 한 프레임에 남은 거리의 0.14만큼 다가간다는 뜻이다.
디스플레이 주사율과 관계없이 같은 속도가 되도록, 지난 프레임과의 시간 차 `Δt`(ms)로 그 프레임의 비율을 구한다.

```
k = 1 − (1 − 0.14)^(Δt × 60 / 1000)
현재 += (목표 − 현재) × k
```

60fps(`Δt` ≈ 16.7)에서는 k = 0.14, 120fps에서는 한 프레임에 약 0.073이 되어 1초 동안 다가가는 정도가 같다.
